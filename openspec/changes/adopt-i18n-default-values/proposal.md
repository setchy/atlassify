# Proposal

## Why

The primary locale `en.json` is hand-maintained. When a developer adds a new `t('some.key')` call, `i18next-cli extract` writes an **empty string** into `en.json` (verified empirically) — so English users see the raw dotted key or blank text until someone manually fills in the English value. The extractor is designed to *generate* the primary locale from code — specifically from `defaultValue` in `t()` calls — so the toolchain can always seed new keys. This change makes the English source of truth live in code (as `defaultValue`), eliminating empty keys permanently and making call sites self-documenting.

## What Changes

- Every `t()` call gains a `defaultValue` holding the canonical English text (taken from the current `en.json` values, so rendered output is byte-identical).
  - Components via `useTranslation()` (19+ files).
  - Utility modules via the `i18n.t()` singleton (`filters/*.ts`, `display.ts`, `native.ts`, `api/*`).
  - The `Errors` catalog getters in `utils/core/errors.ts` (the managed strings from PR #3829).
- `en.json` becomes a **generated mirror** of code defaults: `i18n:extract` regenerates it, and the English now lives in `defaultValue` at each call site. Copy editing happens in code.
- A new key convention: **every `t()` call MUST include a `defaultValue`**.
- A CI guard fails if any `en.json` primary-locale value is empty or identical to a dotted key (catches a forgotten `defaultValue`).
- Explicitly documented no-go: **do not enable `--trust-derived`** — empirically it overwrites existing hand-authored English (`"Loading"` → `"loading.heading"`) for every key lacking an explicit default.

## Capabilities

No spec-level behavior changes: this is a pure refactor plus tooling (translated output is unchanged). `skip_specs: true` is set in `.openspec.yaml`.

## Impact

- **Code**: ~20 renderer files — routes (`Accounts`, `Login`, `Landing`, `Filters`, `Notifications`, `Settings`, `ManageAccount`), components (`Sidebar`, `Oops`, `Loading`, `AllRead`, notification components, settings components), and utils (`utils/core/errors.ts`, `utils/notifications/filters/*.ts`, `utils/ui/display.ts`, `utils/system/native.ts`, `utils/api/errors.ts` + `pagination.ts`).
- **Translations**: all 4 locale files regenerated by extract (values unchanged for `en`; other locales unaffected).
- **Tooling**: CI/check script for empty `en.json` values; `i18next.config.ts` unchanged unless the guard is hosted there.
- **Docs**: `CONTRIBUTING.md` locale section updated with the `defaultValue` convention.
- **Tests**: unchanged — engine-string values are identical; existing suites assert the same text.
